## 一、DNS:不只是「域名转 IP」

**DNS = Domain Name System,「域名系统」**——注意结尾是「**系统(System)**」,不是「服务」。

它最出名的用途是「域名 → IP 地址」,但这只是冰山一角。**DNS 的本质是一个分布式的、按「名字 + 记录类型(type)」查询的命名数据库**。查询的关键不止「名字」,还有一个「你想要哪种类型的记录」。同一个名字,问不同类型,返回不同结果:

| 记录类型 | 全称 | 作用 |
|----------|------|------|
| **A** | Address | 域名 → IPv4 地址(最常用) |
| **AAAA** | (IPv6 Address) | 域名 → IPv6 地址 |
| **PTR** | Pointer | 「指针」记录,见下 |
| **SRV** | Service | 「服务定位」记录,见下 |
| **TXT** | Text | 任意文本 / 键值对元数据 |
| **CNAME** | Canonical Name | 别名 → 另一个域名 |
| **MX** | Mail Exchange | 域名 → 邮件服务器 |

所以「DNS 原来不只支持域名、还支持服务」——准确说是:**DNS 一直是个通用命名数据库**,「域名→IP」只是它最出名的那个用途而已。

## 二、PTR 与 SRV:服务发现靠的两块基石

**SRV = Service record,「服务定位记录」。** 它回答「**某个服务在哪台主机的哪个端口**」。格式大致是:

{% highlight text %}
_service._proto.name   →   优先级  权重  端口   目标主机名
例:_ipp._tcp.local.    →    0      0    631   printer.local.
{% endhighlight %}

它比 A 记录多了**端口**(还有优先级/权重可用于负载均衡)。设备发现里「拿到 host:port」靠的就是它。

**PTR = Pointer record,「指针记录」。** 它有两个容易混淆的用途:

1. **传统 DNS 里**:做**反向解析**——`IP → 域名`(和 A 记录方向相反)。
2. **在服务发现里**:做**服务枚举**——`服务类型 → 有哪些服务实例`。浏览方先问「这类服务网络里都有谁?」,PTR 返回一串实例名。

## 三、DNS-SD:用现成记录拼出「服务发现」

**DNS-SD = DNS Service Discovery,「基于 DNS 的服务发现」。** 它的聪明之处在于:**不发明任何新协议**,而是复用上面 PTR / SRV / TXT 这几种现成的 DNS 记录,拼出一整套「发现服务」的语义。

一次完整发现的链路:

{% highlight text %}
PTR        →  这类服务有哪些实例(枚举)
 │
 ▼
SRV        →  某实例在哪台主机的哪个端口
 │
 ▼
A / AAAA   →  那台主机的 IP
 │
 ▼
TXT        →  实例的元数据(版本、标识、分组……)
{% endhighlight %}

## 四、单播 / 广播 / 多播:一份数据发给谁

这三个词的区别,本质是「一份数据的目标是谁」:

- **单播(Unicast)**:**一对一**。发给某个确切的 IP。你刷网页、发消息,都是单播。
- **广播(Broadcast)**:**一对所有**。发给本网段里**每一台**设备,不管它想不想要——容易打扰所有人。
- **多播 / 组播(Multicast)**:**一对一组**。只发给「**加入了某个多播组**」的设备,没加入的收不到。

**所谓「多播信道」,就是这个多播组**——由一个特殊的多播地址标识。比如 mDNS 用的是 `224.0.0.251:5353`(IPv6 为 `FF02::FB`):所有想参与 mDNS 的设备都「加入」这个组,往这个地址发的包,组内成员都收得到,组外设备与网络其它部分则不受打扰。**多播 = 比广播更精准、更省、更干净的「定向群发」。**

> 设备怎么「加入」多播组?靠链路层的 **IGMP(IPv4)/ MLD(IPv6)** 协议向交换机/路由器登记成员关系。

## 五、广播的实现:发送、接收与监听

广播怎么落到代码?机制先记几条:**只能用 UDP**(TCP 是面向连接的点对点,天生不能广播)、**不需要"加入组"**(网段内人人都收,这是和组播最大的区别)、**受限于广播域**(默认不跨路由器)。广播地址有两种:

- **受限广播 `255.255.255.255`**:发给**本网段**所有主机,路由器绝不转发。
- **子网定向广播**:子网广播地址(主机位全 1),如 `192.168.1.0/24` 的 `192.168.1.255`。

链路层上,广播映射到 MAC `FF:FF:FF:FF:FF:FF`,交换机泛洪到所有端口。

**发送**:建 UDP socket → **开 `SO_BROADCAST`**(系统默认禁止广播发送,必须显式开)→ 向广播地址 `sendto`。

{% highlight javascript %}
// 发送方（Node.js dgram 示意）
const sock = require('dgram').createSocket('udp4');
sock.bind(() => {
  sock.setBroadcast(true);                       // ← 关键：开启 SO_BROADCAST
  sock.send(Buffer.from('HELLO-LAN'), 50000, '255.255.255.255');
});
{% endhighlight %}

**接收 / 监听**:比组播简单——**没有"加入组"这一步**,只要把 UDP socket 绑到端口就能收。建 socket → 开 `SO_REUSEADDR` → **绑定到 `0.0.0.0`(通配地址)的目标端口** → 收包循环。

{% highlight javascript %}
// 接收方 / 监听（Node.js dgram 示意）
const recv = require('dgram').createSocket({ type: 'udp4', reuseAddr: true });
recv.on('message', (msg, rinfo) => {
  // rinfo.address/port = 发送方，可据此回单播
  console.log(`收到广播 ${msg} 来自 ${rinfo.address}:${rinfo.port}`);
});
recv.bind(50000, '0.0.0.0');                     // 绑通配地址；别绑具体单播 IP
{% endhighlight %}

两个关键坑:**① 必须绑 `0.0.0.0`(INADDR_ANY),绑具体网卡 IP 在某些系统下收不到广播;② 同机多进程/快速重启要 `SO_REUSEADDR`,否则 `bind` 报端口占用。**

**广播 vs 组播**——这正是 mDNS 选组播的原因:

| | 广播(Broadcast) | 组播(Multicast) |
|---|---|---|
| 目标 | 网段内**所有**主机 | 只发给**加入了组**的主机 |
| 打扰面 | 打扰所有人(无关主机也得收、解包再丢) | 只打扰订阅者,更省 |
| 成员管理 | 无,人人都收 | 靠 IGMP/MLD 登记 |
| 跨网段 | 默认不跨 | 默认不跨(链路本地) |
| 现网支持 | 不少 WiFi/企业网**限制甚至禁用** | 也可能被 IGMP snooping 影响 |

> 一句话:**广播是"无差别群发",组播是"按订阅精准群发"**。mDNS 用组播,就是为了不打扰整个网段、只让关心该服务的设备收到——所以 `224.0.0.251:5353` 是组播地址,不是广播地址。

## 六、广播域:决定了 mDNS 的边界

**广播域(Broadcast Domain)= 一个广播包能到达的范围**——也就是「彼此之间能用链路层广播直接互通」的那一组设备。

记住两条关键规则:

- **交换机(switch)不分割广播域**:广播会在交换机连接的所有端口里扩散。
- **路由器(router)分割广播域**:**路由器默认不转发广播,也不转发链路本地的多播**。

所以**一个典型的广播域 ≈ 一个 LAN 网段 / 一个 VLAN**。

这条规则直接解释了 mDNS 一个最重要的限制:**mDNS 默认不跨路由器、不跨子网**——因为它依赖的链路本地多播出不了广播域。落到现实里就是:

- 手机和电视连**同一个 WiFi**,能互相发现;
- 一旦它们被分到**不同 VLAN / 访客网络隔离**,就互相扫不到了——它们根本不在同一个广播域里。

排查「设备明明在同一栋楼却扫不到」时,九成是卡在广播域:跨网段了、AP 开了客户端隔离、或交换机的 IGMP snooping 把多播吞了。

## 七、一句话串起来

把这几个概念连成一条线,设备发现的全貌就清楚了:

> **DNS 是个按「名字 + 类型」查的命名数据库 → DNS-SD 复用 PTR/SRV/TXT 表达「服务发现」 → mDNS 把这套问答放到「多播信道」上做无中心广播 → 而多播信道受限于「广播域」,所以发现只能在同一网段内进行。**
